# 标准化 OpenSpec 文档

## 问题陈述

当前项目的 OpenSpec 文档存在多个问题，影响了可读性和一致性：
- 语言不统一（部分英文，部分中文）
- 内容重复（project.md 和 project-spec.md 内容高度相似）
- 信息过时（i18n.md 提到已废弃的 next-intl 配置）
- 结构不规范（缺少标准 OpenSpec 文档结构）
- 格式和风格不统一

## 提议方案

### 目标
- **统一语言**：所有 OpenSpec 文档使用中文
- **简化结构**：保持现有文件组织，但优化内容
- **消除重复**：合并重复文档，确保信息单一真实源
- **更新内容**：移除过时信息，反映最新代码状态

### 具体变更
1. 重写 `features.md` 为中文
2. 更新 `i18n.md` 移除过时信息
3. 合并 `project.md` 和 `project-spec.md`
4. 完善现有文档的准确性
5. 更新 README.md 索引
6. 保持文档简洁概要（每个文档 1-2 页）

### 范围
仅涉及 `/workspace/openspec/` 目录下的文档文件，不修改任何生产代码。

## 理由

清晰、一致、准确的文档对于项目维护至关重要。统一的中文文档可以让团队成员更容易理解项目规范，避免误解。消除重复内容可以减少维护成本，确保信息一致性。

## 风险和开放性问题

| 风险 | 缓解措施 |
|------|---------|
| 文档更新可能遗漏细节 | 参考现有代码库验证所有信息 |
| 可能需要后续迭代完善 | 将文档规范纳入项目规则 |

## 非目标

- 不创建完整的 OpenSpec 完整文档集（暂不添加 spec.md、design.md 等）
- 不翻译所有历史文档（只更新现有 openspec 目录）
- 不添加英文翻译版本
